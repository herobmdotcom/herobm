# Make Targets Guide

This repository uses a `Makefile` to simplify and standardize the orchestration of the various Docker containers, development scripts, and verification tests that make up the ModBM platform.

Below is an overview of the primary commands available.

## Core Setup & Fast Initialization

- **`make setup`**
  The primary entry point. Generates `.env` variables and automatically provisions the databases, runs migrations, extracts ABM data, compiles dbt models, and seeds required demo users.
  
- **`make setup-no-extract`** / **`make init-no-extract`**
  Fast-path variants of the setup/init process that safely skip the lengthy ABM `dlt` extraction phase. Useful for resuming a failed setup when staging data has already been successfully downloaded.

## Containerized Stacks (`up-*` and `down-*`)

ModBM utilizes Docker Compose profiles to logically isolate different operational domains. The `make` commands cleanly wrap these targets.

- **`make up-db`** / **`make down-db`**
  The "Local Native" path. Starts only `postgres-custom` and `redis-broker`. Use this when you intend to run the API and Frontend locally via Node.js for maximum hot-reloading developer performance.

- **`make up-fe-api`** / **`make down-fe-api`**
  The "Full Containerization" path. Starts the `custom-api`, `ops-portal`, `postgres-custom`, and `redis-broker` fully containerized. Recommended for evaluation and ops.

- **`make up-plg`** / **`make down-plg`**
  Starts the observability stack (Prometheus, Loki, Grafana, Promtail). These containers silently hook into the Docker logs and metrics endpoints generated by the `fe-api` stack. 

- **`make up-erpnext`** / **`make down-erpnext`**
  Spins up the entire ERPNext suite (Frappe backend, MariaDB database, dedicated Redis caches, schedulers, and workers). This stack connects to the `app-net` to allow the ModBM Worker to relay data, but otherwise operates independently.

- **`make up-queue`** / **`make down-queue`**
  Starts the `outbox-worker` container (which requires `redis-broker` and ERPNext to be running). The worker polls the ModBM database and processes domain events via BullMQ.

- **`make up-all`** / **`make down-all`**
  A wildcard command that brings up absolutely every service across all profiles simultaneously (FE, API, Postgres, Redis, PLG, Queue, and ERPNext).

## Verification & Quality Gates

Before merging PRs or deploying, you can use these bundled commands to ensure the codebase remains structurally sound:

- **`make verify-fe-api`**
  Runs the TypeScript compiler across the frontend (`typecheck-portal`), executes the NestJS unit tests (`test-api`), and runs the API's automated End-to-End endpoints (`test-api-e2e`). This ensures the core application works without rebuilding images.

- **`make test-structural`**
  Executes the Constitution enforcement scripts (checking for wildcard CORS, hardcoded secrets, misconfigured Docker sockets, etc.).

- **`make verify-all`**
  Runs the complete battery of tests: structural checks, dependency checks, `dbt` transform tests, and the `verify-fe-api` loop.

## ELT Pipeline Commands

The pipeline orchestrating data integration from legacy MSSQL systems into the `modbm_core` database uses several targets:

- **`make extract`** — Runs the Python `dlt` pipeline locally to extract state.
- **`make transform`** — Executes `dbt run` locally to build the data marts.
- **`make elt`** — Runs full extraction, transformation, and schema generation chronologically.
- **`make elt-no-extract`** — Runs transformation and schema generation only, bypassing the Python extraction step.
